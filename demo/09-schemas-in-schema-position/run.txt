===== [1] additionalProperties: the schema for the extra properties ==========

"additionalProperties" gives the schema that every extra property of an
object must satisfy -- extra meaning any property that "properties" does not
name. The schema below names one string property, "a", and requires every
other property to be a number. It is checked against two instances identical
except for the type of "b": the verdict turns on that one difference.

----- [2] extras must be numbers ---------------------------------------------

$ cat schema-number.json
{
  "type": "object",
  "properties": { "a": { "type": "string" } },
  "additionalProperties": { "type": "number" }
}

----- [3] extra b is a number ------------------------------------------------

$ cat instance-number.json
{
  "a": "hello",
  "b": 1
}

----- [4] jsonschema (Python): extra b is a number ---------------------------

$ jsonschema-validate --schema schema-number.json --instance instance-number.json
VALID

----- [5] ajv (JavaScript): extra b is a number ------------------------------

$ ajv-validate --schema schema-number.json --instance instance-number.json
VALID

----- [6] extra b is a string ------------------------------------------------

$ cat instance-string.json
{
  "a": "hello",
  "b": "x"
}

----- [7] jsonschema (Python): extra b is a string ---------------------------

$ jsonschema-validate --schema schema-number.json --instance instance-string.json
INVALID: /b: 'x' is not of type 'number'

----- [8] ajv (JavaScript): extra b is a string ------------------------------

$ ajv-validate --schema schema-number.json --instance instance-string.json
INVALID: /b: must be number

===== [9] false, true, and {} in the same position ===========================

Because the value is a schema, true and false can stand in this position
too, and they mean what demo 01 showed: false rejects every extra property,
so any object with one is rejected; true accepts every extra property; and
{} behaves exactly as true does. Below, one instance with an extra property
is checked against these three schemas, which differ only in the value of
"additionalProperties".

----- [10] the instance ------------------------------------------------------

$ cat instance-number.json
{
  "a": "hello",
  "b": 1
}

----- [11] extras forbidden (additionalProperties false) ---------------------

$ cat schema-false.json
{
  "type": "object",
  "properties": { "a": { "type": "string" } },
  "additionalProperties": false
}

----- [12] jsonschema (Python): extras forbidden -----------------------------

$ jsonschema-validate --schema schema-false.json --instance instance-number.json
INVALID: Additional properties are not allowed ('b' was unexpected)

----- [13] ajv (JavaScript): extras forbidden --------------------------------

$ ajv-validate --schema schema-false.json --instance instance-number.json
INVALID: must NOT have additional properties

----- [14] extras allowed (additionalProperties true) ------------------------

$ cat schema-true.json
{
  "type": "object",
  "properties": { "a": { "type": "string" } },
  "additionalProperties": true
}

----- [15] jsonschema (Python): extras allowed -------------------------------

$ jsonschema-validate --schema schema-true.json --instance instance-number.json
VALID

----- [16] ajv (JavaScript): extras allowed ----------------------------------

$ ajv-validate --schema schema-true.json --instance instance-number.json
VALID

----- [17] extras allowed (additionalProperties {}) --------------------------

$ cat schema-empty.json
{
  "type": "object",
  "properties": { "a": { "type": "string" } },
  "additionalProperties": {}
}

----- [18] jsonschema (Python): extras allowed, {} ---------------------------

$ jsonschema-validate --schema schema-empty.json --instance instance-number.json
VALID

----- [19] ajv (JavaScript): extras allowed, {} ------------------------------

$ ajv-validate --schema schema-empty.json --instance instance-number.json
VALID
