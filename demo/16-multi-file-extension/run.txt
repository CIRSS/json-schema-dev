===== [1] a base schema in its own file, validating on its own ===============

Everything so far lived in one file. This demo splits a schema across two:
a base that stands alone, and an overlay that extends it. The base below
declares an id property and requires it — and nothing more. It is
deliberately open: no closure, no opinion about members it does not name.

Four instances run against it, varying one thing at a time: the minimal
record; the same record with a stray member; the record with a status
member the base never mentions; and both additions at once. The base
accepts all four — openness is not an oversight here but the property that
makes the base extendable, and every verdict that follows is evidence of
what the overlay adds, not something the base already did.

----- [2] the base schema ----------------------------------------------------

$ cat base.json
{
  "$id": "https://example.org/schemas/record",
  "type": "object",
  "properties": { "id": { "type": "string" } },
  "required": ["id"]
}

----- [3] the minimal record -------------------------------------------------

$ cat instance-minimal.json
{"id": "r1"}

----- [4] jsonschema (Python): base, minimal ---------------------------------

$ jsonschema-validate --schema base.json --instance instance-minimal.json
VALID

----- [5] ajv (JavaScript): base, minimal ------------------------------------

$ ajv-validate --schema base.json --instance instance-minimal.json
VALID

----- [6] with a stray member ------------------------------------------------

$ cat instance-stray.json
{"id": "r1", "note": "x"}

----- [7] jsonschema (Python): base, stray -----------------------------------

$ jsonschema-validate --schema base.json --instance instance-stray.json
VALID

----- [8] ajv (JavaScript): base, stray --------------------------------------

$ ajv-validate --schema base.json --instance instance-stray.json
VALID

----- [9] with a status ------------------------------------------------------

$ cat instance-full.json
{"id": "r1", "status": "draft"}

----- [10] jsonschema (Python): base, status ---------------------------------

$ jsonschema-validate --schema base.json --instance instance-full.json
VALID

----- [11] ajv (JavaScript): base, status ------------------------------------

$ ajv-validate --schema base.json --instance instance-full.json
VALID

----- [12] with status and a stray member ------------------------------------

$ cat instance-full-stray.json
{"id": "r1", "status": "draft", "note": "x"}

----- [13] jsonschema (Python): base, both -----------------------------------

$ jsonschema-validate --schema base.json --instance instance-full-stray.json
VALID

----- [14] ajv (JavaScript): base, both --------------------------------------

$ ajv-validate --schema base.json --instance instance-full-stray.json
VALID

===== [15] an overlay that extends the base and closes over the union ========

The overlay references the base by its $id (demo 13), adds its own
requirement under allOf (demo 12), and closes the whole with
unevaluatedProperties: false — which sees through both the allOf and the
$ref (demos 14 and 15), so properties declared by the base count as
evaluated. Each validator needs to be handed the base file explicitly
(--ref); the $id is a name to resolve against, not a URL anyone fetches.

The same four instances, in the same order. The minimal record now fails
for lacking status; the stray member now fails closure; the record with
status passes; status plus a stray member fails closure alone. Everything
the base accepted and the overlay rejects is the overlay's doing — the
base file is untouched, still open, and still valid on its own. That is
the extension contract: a base schema usable standalone, and stricter
profiles layered on it by reference, each in its own file.

----- [16] the overlay schema ------------------------------------------------

$ cat overlay.json
{
  "$id": "https://example.org/schemas/record-strict",
  "allOf": [ { "$ref": "https://example.org/schemas/record" } ],
  "properties": { "status": { "type": "string" } },
  "required": ["status"],
  "unevaluatedProperties": false
}

----- [17] jsonschema (Python): overlay, minimal -----------------------------

$ jsonschema-validate --schema overlay.json --ref base.json --instance instance-minimal.json
INVALID: 'status' is a required property

----- [18] ajv (JavaScript): overlay, minimal --------------------------------

$ ajv-validate --schema overlay.json --ref base.json --instance instance-minimal.json
INVALID: must have required property 'status'

----- [19] jsonschema (Python): overlay, stray -------------------------------

$ jsonschema-validate --schema overlay.json --ref base.json --instance instance-stray.json
INVALID: 'status' is a required property
INVALID: Unevaluated properties are not allowed ('note' was unexpected)

----- [20] ajv (JavaScript): overlay, stray ----------------------------------

$ ajv-validate --schema overlay.json --ref base.json --instance instance-stray.json
INVALID: must have required property 'status'
INVALID: must NOT have unevaluated properties

----- [21] jsonschema (Python): overlay, status ------------------------------

$ jsonschema-validate --schema overlay.json --ref base.json --instance instance-full.json
VALID

----- [22] ajv (JavaScript): overlay, status ---------------------------------

$ ajv-validate --schema overlay.json --ref base.json --instance instance-full.json
VALID

----- [23] jsonschema (Python): overlay, both --------------------------------

$ jsonschema-validate --schema overlay.json --ref base.json --instance instance-full-stray.json
INVALID: Unevaluated properties are not allowed ('note' was unexpected)

----- [24] ajv (JavaScript): overlay, both -----------------------------------

$ ajv-validate --schema overlay.json --ref base.json --instance instance-full-stray.json
INVALID: must NOT have unevaluated properties

===== [25] the overlay is not self-contained, and says so ====================

One last run, differing from the passing case in one way: the --ref is
omitted. Both validators refuse — an error, not a verdict — because the
overlay's $ref now resolves to nothing. They refuse at their usual
different moments (demo 12): Ajv while compiling, jsonschema during
validation. A multi-file schema is a set of files that must travel
together, and the error is the reminder.

----- [26] jsonschema (Python): overlay without --ref ------------------------

$ jsonschema-validate --schema overlay.json --instance instance-full.json
jsonschema-validate: error: overlay.json contains an unresolvable $ref: Unresolvable: https://example.org/schemas/record

----- [27] ajv (JavaScript): overlay without --ref ---------------------------

$ ajv-validate --schema overlay.json --instance instance-full.json
ajv-validate: error: overlay.json is not a valid JSON Schema: can't resolve reference https://example.org/schemas/record from id https://example.org/schemas/record-strict
