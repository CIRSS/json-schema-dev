===== [1] the same schema, required of every element or of some element ======

Demo 03's "items" holds a schema and requires every element of the
array to satisfy it. "contains" holds a schema and requires that
some element satisfy it: the array is accepted when at least one
does, and nothing is required of the rest. What each holds is a
complete schema -- any schema (demo 09) -- so a "contains" can
state whatever requirement the data calls for, and the sections
below put several in that position.

The two schemas below hold the same schema, {"type": "number"},
and differ only in the keyword carrying it. The instance holds a
string and a number. Under "items" the string is a violation;
under "contains" the number is enough.

----- [2] an array with a string and a number --------------------------------

$ cat instance-string-number.json
["a", 5]

----- [3] every element a number ---------------------------------------------

$ cat schema-items-number.json
{
  "type": "array",
  "items": { "type": "number" }
}

----- [4] jsonschema (Python): items -----------------------------------------

$ jsonschema-validate --schema schema-items-number.json --instance instance-string-number.json
INVALID: /0: 'a' is not of type 'number'

----- [5] ajv (JavaScript): items --------------------------------------------

$ ajv-validate --schema schema-items-number.json --instance instance-string-number.json
INVALID: /0: must be number

----- [6] some element a number ----------------------------------------------

$ cat schema-contains-number.json
{
  "type": "array",
  "contains": { "type": "number" }
}

----- [7] jsonschema (Python): contains --------------------------------------

$ jsonschema-validate --schema schema-contains-number.json --instance instance-string-number.json
VALID

----- [8] ajv (JavaScript): contains -----------------------------------------

$ ajv-validate --schema schema-contains-number.json --instance instance-string-number.json
VALID

===== [9] when no element satisfies the schema ===============================

The array below holds no number, so the "contains" is not
satisfied and both validators reject it. jsonschema reports one
error for the array. Ajv reports three: it returns every
assertion failure met during evaluation -- here, each element's
failure to be the matching element, then the "contains" failure
those two produced. The errors are structured objects that a
consuming program is expected to sift; the wrappers used here
print each one as a line, which gives a sub-result the same
standing as the conclusion. So read the lines knowing their
roles: "/0: must be number" states no obligation -- no element
must be a number -- and the requirement actually violated is the
final line's. On a long array, one missing element produces a
line for each innocent element.

----- [10] an array of two strings -------------------------------------------

$ cat instance-two-strings.json
["a", "b"]

----- [11] jsonschema (Python): no number ------------------------------------

$ jsonschema-validate --schema schema-contains-number.json --instance instance-two-strings.json
INVALID: ['a', 'b'] does not contain items matching the given schema

----- [12] ajv (JavaScript): no number ---------------------------------------

$ ajv-validate --schema schema-contains-number.json --instance instance-two-strings.json
INVALID: /0: must be number
INVALID: /1: must be number
INVALID: must contain at least 1 valid item(s)

===== [13] the empty array ===================================================

Demo 03 showed [] accepted by any "items" schema: with no
elements, there is no element to reject. The same emptiness has
the opposite effect on "contains": there is no element to
satisfy it, so [] fails every "contains".

----- [14] the empty array ---------------------------------------------------

$ cat instance-empty.json
[]

----- [15] jsonschema (Python): empty array, items ---------------------------

$ jsonschema-validate --schema schema-items-number.json --instance instance-empty.json
VALID

----- [16] ajv (JavaScript): empty array, items ------------------------------

$ ajv-validate --schema schema-items-number.json --instance instance-empty.json
VALID

----- [17] jsonschema (Python): empty array, contains ------------------------

$ jsonschema-validate --schema schema-contains-number.json --instance instance-empty.json
INVALID: [] does not contain items matching the given schema

----- [18] ajv (JavaScript): empty array, contains ---------------------------

$ ajv-validate --schema schema-contains-number.json --instance instance-empty.json
INVALID: must contain at least 1 valid item(s)

===== [19] a contains that describes a shape =================================

The schema in a "contains" can describe as much as any schema
can. Below it describes an object with a string member "id" and
requires that member, so the array must hold at least one record
carrying an "id".

The first array below has one element without "id" and one with
it -- accepted, the element lacking "id" costing nothing. In the
second no element carries "id", and the array is rejected.

----- [20] some element a record with an id ----------------------------------

$ cat schema-contains-record.json
{
  "type": "array",
  "contains": {
    "type": "object",
    "properties": { "id": { "type": "string" } },
    "required": ["id"]
  }
}

----- [21] one element carries id --------------------------------------------

$ cat instance-one-record.json
[
  { "note": "x" },
  { "id": "r1", "status": "draft" }
]

----- [22] jsonschema (Python): id present -----------------------------------

$ jsonschema-validate --schema schema-contains-record.json --instance instance-one-record.json
VALID

----- [23] ajv (JavaScript): id present --------------------------------------

$ ajv-validate --schema schema-contains-record.json --instance instance-one-record.json
VALID

----- [24] no element carries id ---------------------------------------------

$ cat instance-no-record.json
[
  { "note": "x" },
  { "status": "draft" }
]

----- [25] jsonschema (Python): id absent ------------------------------------

$ jsonschema-validate --schema schema-contains-record.json --instance instance-no-record.json
INVALID: [{'note': 'x'}, {'status': 'draft'}] does not contain items matching the given schema

----- [26] ajv (JavaScript): id absent ---------------------------------------

$ ajv-validate --schema schema-contains-record.json --instance instance-no-record.json
INVALID: /0: must have required property 'id'
INVALID: /1: must have required property 'id'
INVALID: must contain at least 1 valid item(s)

===== [27] the narrow end: a contains that names one value ===================

A "const" (demo 10) is satisfied by exactly one value, so a
"contains" holding one requires the array to carry that value
somewhere -- position free, as always. The schemas below take
that form, and it is the form a JSON-LD "@context" needs: an
array required to carry one published entry, whatever else it
also carries.

The second schema names an object. A "const" compares by JSON
equality (demo 10), so the order of an object's members does not
matter and every member matters: the array with the object's
members written in the other order is accepted, and the array
whose element carrying "p1" is missing the second member is
rejected.

----- [28] some element equal to core ----------------------------------------

$ cat schema-contains-core.json
{
  "type": "array",
  "contains": { "const": "core" }
}

----- [29] core between two other elements -----------------------------------

$ cat instance-ext1-core-ext2.json
["ext1", "core", "ext2"]

----- [30] jsonschema (Python): core present ---------------------------------

$ jsonschema-validate --schema schema-contains-core.json --instance instance-ext1-core-ext2.json
VALID

----- [31] ajv (JavaScript): core present ------------------------------------

$ ajv-validate --schema schema-contains-core.json --instance instance-ext1-core-ext2.json
VALID

----- [32] some element equal to an object -----------------------------------

$ cat schema-contains-object.json
{
  "type": "array",
  "contains": {
    "const": { "p1": "https://example.org/ns1", "p2": "https://example.org/ns2" }
  }
}

----- [33] the object's members reordered ------------------------------------

$ cat instance-object-reordered.json
[
  { "p2": "https://example.org/ns2", "p1": "https://example.org/ns1" },
  { "p3": "https://example.org/ns3" }
]

----- [34] jsonschema (Python): members reordered ----------------------------

$ jsonschema-validate --schema schema-contains-object.json --instance instance-object-reordered.json
VALID

----- [35] ajv (JavaScript): members reordered -------------------------------

$ ajv-validate --schema schema-contains-object.json --instance instance-object-reordered.json
VALID

----- [36] one member missing from the object --------------------------------

$ cat instance-object-short.json
[
  { "p1": "https://example.org/ns1" },
  { "p3": "https://example.org/ns3" }
]

----- [37] jsonschema (Python): member missing -------------------------------

$ jsonschema-validate --schema schema-contains-object.json --instance instance-object-short.json
INVALID: [{'p1': 'https://example.org/ns1'}, {'p3': 'https://example.org/ns3'}] does not contain items matching the given schema

----- [38] ajv (JavaScript): member missing ----------------------------------

$ ajv-validate --schema schema-contains-object.json --instance instance-object-short.json
INVALID: /0: must be equal to constant
INVALID: /1: must be equal to constant
INVALID: must contain at least 1 valid item(s)

===== [39] items and contains combine in one schema object ===================

An array schema can hold both "items" and "contains". No "allOf"
is needed -- they are different keywords, and a schema object is
an and of its keywords (demo 08), so both requirements are in
force. In the schema below, every element must be a string, and
some element must equal "core".

The first array below satisfies both requirements. The second
includes "core" but also a number, and the "items" rejects the
number at /1. The third holds only strings, none of them "core",
and the "contains" rejects the array.

----- [40] every element a string, some element core -------------------------

$ cat schema-items-and-contains.json
{
  "type": "array",
  "items": { "type": "string" },
  "contains": { "const": "core" }
}

----- [41] jsonschema (Python): core among strings ---------------------------

$ jsonschema-validate --schema schema-items-and-contains.json --instance instance-ext1-core-ext2.json
VALID

----- [42] ajv (JavaScript): core among strings ------------------------------

$ ajv-validate --schema schema-items-and-contains.json --instance instance-ext1-core-ext2.json
VALID

----- [43] a number beside core ----------------------------------------------

$ cat instance-core-5.json
["core", 5]

----- [44] jsonschema (Python): a number beside core -------------------------

$ jsonschema-validate --schema schema-items-and-contains.json --instance instance-core-5.json
INVALID: /1: 5 is not of type 'string'

----- [45] ajv (JavaScript): a number beside core ----------------------------

$ ajv-validate --schema schema-items-and-contains.json --instance instance-core-5.json
INVALID: /1: must be string

----- [46] strings without core ----------------------------------------------

$ cat instance-ext1-ext2.json
["ext1", "ext2"]

----- [47] jsonschema (Python): strings without core -------------------------

$ jsonschema-validate --schema schema-items-and-contains.json --instance instance-ext1-ext2.json
INVALID: ['ext1', 'ext2'] does not contain items matching the given schema

----- [48] ajv (JavaScript): strings without core ----------------------------

$ ajv-validate --schema schema-items-and-contains.json --instance instance-ext1-ext2.json
INVALID: /0: must be equal to constant
INVALID: /1: must be equal to constant
INVALID: must contain at least 1 valid item(s)

===== [49] two required elements: one contains per allOf branch ==============

A schema object can hold only one member named "contains", so
requiring two different elements takes an "allOf" (demo 12), one
"contains" per branch. The schema below requires an element
equal to "core" and an element equal to "ext1". The first array
below carries both and passes; the second lacks "ext1", and the
branch that requires it rejects the array.

----- [50] requiring both core and ext1 --------------------------------------

$ cat schema-two-contains.json
{
  "type": "array",
  "allOf": [
    { "contains": { "const": "core" } },
    { "contains": { "const": "ext1" } }
  ]
}

----- [51] jsonschema (Python): both present ---------------------------------

$ jsonschema-validate --schema schema-two-contains.json --instance instance-ext1-core-ext2.json
VALID

----- [52] ajv (JavaScript): both present ------------------------------------

$ ajv-validate --schema schema-two-contains.json --instance instance-ext1-core-ext2.json
VALID

----- [53] ext1 missing ------------------------------------------------------

$ cat instance-core-ext2.json
["core", "ext2"]

----- [54] jsonschema (Python): ext1 missing ---------------------------------

$ jsonschema-validate --schema schema-two-contains.json --instance instance-core-ext2.json
INVALID: ['core', 'ext2'] does not contain items matching the given schema

----- [55] ajv (JavaScript): ext1 missing ------------------------------------

$ ajv-validate --schema schema-two-contains.json --instance instance-core-ext2.json
INVALID: /0: must be equal to constant
INVALID: /1: must be equal to constant
INVALID: must contain at least 1 valid item(s)

===== [56] blocking a value with not =========================================

Keeping "core" out of the array is the opposite requirement, a
negation, and "not" (demo 08) writes it with either keyword. The
first schema below wraps "not" around a "contains": an array
that contains "core" is rejected. The second puts "not" inside
"items": every element must differ from "core". The two accept
and reject exactly the same arrays -- no element equals "core"
and every element differs from "core" are one requirement,
written two ways.

The verdicts below are identical; the messages are not. The
first form reports at the array, Ajv without even a location;
the second reports at /1, the JSON Pointer naming the element
that broke the rule. Where a value must be kept out, the "items"
form tells the author which element to fix.

----- [57] rejecting arrays that contain core --------------------------------

$ cat schema-not-contains.json
{
  "type": "array",
  "not": { "contains": { "const": "core" } }
}

----- [58] jsonschema (Python): not contains, core present -------------------

$ jsonschema-validate --schema schema-not-contains.json --instance instance-ext1-core-ext2.json
INVALID: ['ext1', 'core', 'ext2'] should not be valid under {'contains': {'const': 'core'}}

----- [59] ajv (JavaScript): not contains, core present ----------------------

$ ajv-validate --schema schema-not-contains.json --instance instance-ext1-core-ext2.json
INVALID: must NOT be valid

----- [60] jsonschema (Python): not contains, core absent --------------------

$ jsonschema-validate --schema schema-not-contains.json --instance instance-ext1-ext2.json
VALID

----- [61] ajv (JavaScript): not contains, core absent -----------------------

$ ajv-validate --schema schema-not-contains.json --instance instance-ext1-ext2.json
VALID

----- [62] requiring every element to differ from core -----------------------

$ cat schema-items-not.json
{
  "type": "array",
  "items": { "not": { "const": "core" } }
}

----- [63] jsonschema (Python): items not, core present ----------------------

$ jsonschema-validate --schema schema-items-not.json --instance instance-ext1-core-ext2.json
INVALID: /1: 'core' should not be valid under {'const': 'core'}

----- [64] ajv (JavaScript): items not, core present -------------------------

$ ajv-validate --schema schema-items-not.json --instance instance-ext1-core-ext2.json
INVALID: /1: must NOT be valid

----- [65] jsonschema (Python): items not, core absent -----------------------

$ jsonschema-validate --schema schema-items-not.json --instance instance-ext1-ext2.json
VALID

----- [66] ajv (JavaScript): items not, core absent --------------------------

$ ajv-validate --schema schema-items-not.json --instance instance-ext1-ext2.json
VALID
