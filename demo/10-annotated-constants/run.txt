===== [1] two ways to say 'one of these exact values' ========================

A fixed set of allowed values is usually written as an "enum": a list of
JSON values of any kinds -- strings, numbers, objects, null -- satisfied by
an instance equal to any one of them. The same set can be written as a
"oneOf" whose entries each hold a "const" -- the keyword satisfied only by
one exact JSON value -- one entry per allowed value. The two schemas below
both allow exactly the strings "draft" and "final", and every verdict that
follows agrees across both schemas and both validators.

What the "oneOf" form adds is a place for a description of each value. An
"enum" can carry a "description" for the whole list but not for its
members; each entry of a "oneOf" is a schema, so each can carry its own
"description" saying what choosing that value means. The documentation
sits next to the value it documents, inside the schema.

----- [2] the enum schema ----------------------------------------------------

$ cat schema-enum.json
{"enum": ["draft", "final"]}

----- [3] the annotated oneOf schema -----------------------------------------

$ cat schema-oneof.json
{
  "oneOf": [
    { "const": "draft", "description": "not yet reviewed; content may change" },
    { "const": "final", "description": "reviewed and frozen; content is fixed" }
  ]
}

----- [4] a value in the set -------------------------------------------------

$ cat instance-known.json
"draft"

----- [5] jsonschema (Python): enum, known -----------------------------------

$ jsonschema-validate --schema schema-enum.json --instance instance-known.json
VALID

----- [6] ajv (JavaScript): enum, known --------------------------------------

$ ajv-validate --schema schema-enum.json --instance instance-known.json
VALID

----- [7] jsonschema (Python): oneOf, known ----------------------------------

$ jsonschema-validate --schema schema-oneof.json --instance instance-known.json
VALID

----- [8] ajv (JavaScript): oneOf, known -------------------------------------

$ ajv-validate --schema schema-oneof.json --instance instance-known.json
VALID

===== [9] the same rejection, at different lengths ===========================

A value outside the set is rejected by both schemas in both validators.
The reports differ in length. For the "enum", each validator gives one
line (Python's names the allowed values; Ajv's does not). For the "oneOf",
Python again gives one line, while Ajv reports each entry's failure
separately and then the summary. The longer report is the cost of the
annotated form; demo 19 shows how a schema can supply its own message in
place of the validator's.

----- [10] a value outside the set -------------------------------------------

$ cat instance-unknown.json
"banana"

----- [11] jsonschema (Python): enum, unknown --------------------------------

$ jsonschema-validate --schema schema-enum.json --instance instance-unknown.json
INVALID: 'banana' is not one of ['draft', 'final']

----- [12] ajv (JavaScript): enum, unknown -----------------------------------

$ ajv-validate --schema schema-enum.json --instance instance-unknown.json
INVALID: must be equal to one of the allowed values

----- [13] jsonschema (Python): oneOf, unknown -------------------------------

$ jsonschema-validate --schema schema-oneof.json --instance instance-unknown.json
INVALID: 'banana' is not valid under any of the given schemas

----- [14] ajv (JavaScript): oneOf, unknown ----------------------------------

$ ajv-validate --schema schema-oneof.json --instance instance-unknown.json
INVALID: must be equal to constant
INVALID: must be equal to constant
INVALID: must match exactly one schema in oneOf

===== [15] values of any kind ================================================

The values in an "enum" need not be strings, and an instance matches by
JSON equality: the number 2 is in the list below and the string "2" is not.
(The "oneOf" form naturally provides the same capability, since each
"const" holds any JSON value.)

----- [16] an enum of a number, a string, and null ---------------------------

$ cat schema-enum-mixed.json
{"enum": [2, "two", null]}

----- [17] the number 2 ------------------------------------------------------

$ cat instance-number-two.json
2

----- [18] jsonschema (Python): mixed, number 2 ------------------------------

$ jsonschema-validate --schema schema-enum-mixed.json --instance instance-number-two.json
VALID

----- [19] ajv (JavaScript): mixed, number 2 ---------------------------------

$ ajv-validate --schema schema-enum-mixed.json --instance instance-number-two.json
VALID

----- [20] the string 2 ------------------------------------------------------

$ cat instance-string-two.json
"2"

----- [21] jsonschema (Python): mixed, string 2 ------------------------------

$ jsonschema-validate --schema schema-enum-mixed.json --instance instance-string-two.json
INVALID: '2' is not one of [2, 'two', None]

----- [22] ajv (JavaScript): mixed, string 2 ---------------------------------

$ ajv-validate --schema schema-enum-mixed.json --instance instance-string-two.json
INVALID: must be equal to one of the allowed values
